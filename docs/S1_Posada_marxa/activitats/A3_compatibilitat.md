## L'encàrrec

<div class="encarrec" markdown>
<p class="meta">De: Direcció · Per a: Equip tècnic</p>

**Assumpte: en quin format enviem les coses?**

Ahir vaig enviar un pressupost a un client i em va contestar que li arribava "tot desmuntat". Jo el veig perfecte ací.

Necessite una norma clara de l'empresa: **en quin format desem i en quin format enviem**. I la vull justificada, no una opinió.
</div>

## El problema

`.odt` i `.docx` no són el mateix format, encara que les dues suites òbriguen els dos. Quan un fitxer passa d'una suite a l'altra, hi ha coses que sobreviuen i coses que no. Saber **quines** és la diferència entre enviar un document i enviar un problema.

## Què has de fer

### 1. Construeix el document de prova

Crea un document que continga, com a mínim:

- Títols amb estils (no text en negreta gran: **estils**).
- Un índex generat automàticament.
- Una taula amb ombrejat i vores.
- Una imatge amb ajust de text al voltant.
- Un peu de pàgina amb numeració automàtica.
- Una nota al peu.
- Un salt de secció amb una pàgina apaïsada.
- Un quadre de text o una forma.

### 2. Fes el viatge d'anada i tornada

1. Desa'l en el format natiu de la teua suite.
2. Obri'l amb l'altra suite (LibreOffice ↔ Microsoft 365 Online).
3. Desa'l des d'ahí en l'altre format.
4. Torna a obrir-lo amb la primera.

### 3. Registra què passa

| Element | Natiu | Obert a l'altra suite | Tornada | Observació |
| --- | --- | --- | --- | --- |
| Estils de títol | | | | |
| Índex automàtic | | | | |
| Taula (ombrejat i vores) | | | | |
| Imatge (ajust de text) | | | | |
| Peu i numeració | | | | |
| Nota al peu | | | | |
| Pàgina apaïsada | | | | |
| Quadre de text | | | | |

Marca cada casella amb 🟢 intacte, 🟡 canvia però s'entén, 🔴 es trenca. Acompanya els 🔴 amb una captura.

### 4. Redacta la política de formats

Tres decisions, cadascuna amb una frase de justificació:

| Situació | Format | Per què |
| --- | --- | --- |
| Document de treball intern, que encara s'edita | | |
| Document que s'envia a un client per a llegir | | |
| Document que s'envia a un client perquè l'edite | | |

!!! tip "Pista que t'estalviarà discussions"
    Fixa't en què passa quan el document ha de conservar **l'aspecte exacte** i què passa quan ha de continuar sent **editable**. Són objectius diferents i no els resol el mateix format.

## Què lliures

Esta activitat **no té lliurament propi**. La taula de proves i la política de formats entren com a **annex de l'informe d'A1**, i és allí on es puntuen.

Tot el curs aplicaràs eixa política: si al març envies un pressupost en un format que contradiu la vostra pròpia norma, es notarà.

## Com s'avalua

**RA1.i · Proposar solucions de programari per a l'entorn d'aplicació — reforç dins d'A1**

- 🟢 Totes les proves fetes i registrades amb evidència gràfica dels problemes. La política de formats distingeix els tres escenaris i cada decisió es justifica amb un resultat concret de la prova.
- 🔵 Proves completes i política coherent, però alguna justificació no s'ancora en el que has observat.
- 🟡 Proves parcials, o la política es limita a *"millor PDF"* sense distingir escenaris.
- 🔴 No hi ha prova real: les conclusions són suposicions o copiades d'Internet.
